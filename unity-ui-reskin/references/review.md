# 界面换皮审查规范

> 适用于美术替换界面资源（贴图、字体、布局、文字样式）之后，评估「要不要改代码、要不要改 prefab」，以及按评估结果落地修复。
> 依据 BubbleWord3 2026-11 的六轮换皮审查实例（宿主 / 经济 / 鱼缸多界面换字体、横版改竖版滚动列表、玩法局内面板整套重做、程序自拼弹窗分支合并）整理成项目无关版。
> `<skill>` = 本 skill 目录。工具说明见 `references/review-tools.md`。项目有自己的审查规范 / 事实库时以项目为准。

## 0. 原则

1. **美术换皮的边界**：只换资源和调整布局，不动层级和功能。审查要找的就是越过这条边界的改动：删改节点、换组件类型、改默认显隐、改多语言 id、挂或去组件、换字体。
2. **先比对再下结论**：每个问题都用「新版 vs 换皮前」区分本轮新引入还是原来就有。原来就有的默认只记录、不顺手修。**例外**：原有问题被本次修复暴露、并在本次交付流程里直接可见或挡住操作，一并修掉，文档标「原有」（例：打开列表遮罩后，遗留的 `maskable=false` 图片画出可视区）。
3. **静态判断要用运行时证实**：静态比对只能找出「可疑」，严重度在 Play 里实测确认。截图看不清时直接读运行时数值（文本、激活状态、滚动位置）。
4. **代码改动最小化**：代码只做适配（组件类型放宽、逻辑改成与方向无关），不重建界面、不绕开规范。文案 id、显隐、层级在 prefab 里修。
5. **修复要保留美术意图**：恢复规范（字体、层级）的同时保留美术这次的视觉效果（描边、阴影、配色、布局），不要整体退回换皮前。
6. **挖完即记**：核实出的项目事实当场记进项目记忆 / 事实库；未闭环事项写进发版提醒清单（项目有的话）。
7. **先评估，再落地**：用户要「审查 / 评估」时先交评估文档，需要决策的项给推荐方案和备选。用户说「直接改 / 以后直接修」时按推荐落地、测试、提交，只有新功能取舍、玩法 / 数值改动才停下来问；给美术的清单照写，标「已由程序修改」作告知。
8. **先摸清美术的设计意图，再改代码**：大的布局改动（横版改竖版、分页改滚动）先在 Play 里临时改运行时值做试验（缩放还原为 1、打开滚动和遮罩、显示被隐藏的节点），看哪种状态和设计对得上，再改代码。
9. 美术提前做了**尚未实现功能**的界面：prefab 保留美术设计，代码在开窗时隐藏，等功能开工再接线。新文字**缺多语言词条**：先找同义词条复用；没有的先隐藏该文字，交策划补词条，不让占位文案上线。美术**原地替换了别的界面也在用的图**：恢复原图，新图另起名，改本次 prefab 的引用。

## 1. 准备与范围

1. 确认范围：美术给的 tag / 起始提交可能在**子模块或独立资源仓库**里（主仓查不到）。工具会自动找包含该提交的仓库（`uir_project.py asset-repo <REV>`）；手动查用 `git -C <资源仓库>`。用户说「某提交之后」BASE 就是该提交；说「这个提交换了这几个界面」时该提交也在范围内，BASE 取 `<提交>^`。区间里非美术提交（配置表、DLL）记一笔即可。资源在子模块时记下主仓当前的子模块指针。
2. 拉远端，确认美术是否仍在提交；修复前提醒用户先和美术沟通，避免冲突。
   - **主仓子模块指针跟到被审提交时，中间夹带的其他美术提交（Spine 等）也会一起进主仓**：至少跑一遍受影响模块的 EditMode 全量，失败项一并修或单列。
3. 统计改动：

   ```bash
   git -C <资源仓库> log --format='%h %an %ad %s' --date=short <BASE>..HEAD
   git -C <资源仓库> diff --stat <BASE>..HEAD -- '*.prefab' | tail -5
   git -C <资源仓库> diff --name-status <BASE>..HEAD | awk '{print $1}' | sort | uniq -c   # 有没有删除（D）
   ```

   按类型分组：prefab、贴图、字体资产、配置表、DLL。有删除的资源单独查谁在引用。
4. 一次报全 git 侧问题（不需要 Unity）：

   ```bash
   python3 -I <skill>/scripts/prefab_audit.py refs  <BASE> HEAD      # 断引用、旧版 UI.Text
   python3 -I <skill>/scripts/prefab_audit.py fonts <BASE> HEAD      # 字体改动汇总
   python3 -I <skill>/scripts/prefab_audit.py locfont <BASE> HEAD    # 本地化组件 + 规范字体（项目不适用时自动跳过）
   ```

## 2. 建立旧版参照

```bash
python3 -I <skill>/scripts/export_snapshot.py <BASE> <对比终点 HEAD> _TmpUIAuditOld
```

- 把 `<BASE>..<终点>` 之间改过的 prefab，以 `<BASE>` 时的内容导出到 `Assets/_TmpUIAuditOld/<Assets 下相对路径>`。不带 `.meta`，Unity 分配新 guid，不和原 prefab 冲突。
- 嵌套 prefab 和 Variant 的引用仍指向**当前版本**的源 prefab：比对时以各自源 prefab 为准，外层只看覆盖值。
- **用完必须删除**（目录和同名 `.meta`）。不能带着它跑测试或提交：有些测试按名字找 prefab，同名副本会干扰。
- 需要「美术版」参照时（修复后对比效果），同一脚本导出美术提交的版本到 `_TmpUIAuditArt`。

## 3. 静态审查清单

Unity 片段在 `<skill>/snippets/review/`，用 MCP `execute_code` 整段运行（只读的加 `skip_refresh=true`），说明见各文件头部。片段遇到项目没有的框架会返回「本项不适用」，照记即可。

| # | 检查项 | 怎么查 | 判据 / 常见后果 |
|---|---|---|---|
| 1 | UI 框架绑定路径和组件 | `BindAudit.cs`（DragonCD3 `[Binding]` 体系）新旧各跑一遍；其他框架 grep 绑定声明 | 只报**新增**的失败。按路径取组件的框架缺节点会抛异常，整窗打不开 |
| 2 | 代码里写死的路径 | `grep -rnE '(Find\|FindChild\|GetItem\|Binding\|transform\.Find)\("…"'`，再用第 3 项的删除节点名反查 | 删改名的节点被代码引用 → 必改 |
| 3 | 层级和组件变化 | `HierDiff.cs`：删除 / 新增节点、组件增减、默认激活翻转、新增同名兄弟、断引用 | 组件类型变化（`Horizontal`↔`VerticalLayoutGroup`、`Text`↔TMP、本地化组件互换）要 grep `GetComponent<T>` / `is T`。同名兄弟会让 `Find` 只命中第一个 |
| 4 | 默认显隐翻转 | 第 3 项的 `ACTIVE` 行，再 grep 代码是否在显示时设置该节点 | 代码会设置的不受影响；不设置的就是功能变化（入口被隐藏、灰态常显）。另查：代码强制显示、美术隐藏并挪位的节点是否重叠；美术新增默认显示的**带 Button 节点**是否盖住原按钮（第 11 项）；反向：美术显示 / 换图的节点被代码在开窗时隐藏或换图（grep `SetActive(false)`、`.sprite =`） |
| 5 | 多语言组件 | `LocCompDiff.cs`：新挂 / 去掉的本地化组件与 id / key / 样式字段变化 | 动态文本新挂 id=0 → 占位值写回。同一节点叠两套多语言组件 → 删多余的。id 改动核对文案语义 |
| 6 | 字体和效果 | `prefab_audit.py fonts` / `locfont`；Unity 侧看材质关键字 | 项目有「本地化组件必须用规范字体」约束时（如 DragonCD3 `LocalizationText` + `TMP_Font_Normal`）：不合规 → 中日韩显示 `□`、切语言不生效。`Resources/` 下的 prefab 引用热更字体 → 开机就是方块、包体重复。记下美术用的效果材质名，修复时保留效果 |
| 7 | 滚动和布局方向 | 第 3 项里 `ScrollRect` / LayoutGroup / 锚点 / pivot 的变化 | 代码里的滚动复位、动画是否只处理一个方向（`horizontalNormalizedPosition`、`DOLocalMoveX`）。列表改成「滚动 + 遮罩」时查列表项图片的 `maskable` 和比卡片大的装饰图的 `raycastTarget` |
| 8 | 断引用 | `prefab_audit.py refs`、`HierDiff` 的 `BROKENREF`；`git diff --name-status` 的删除 | 只报本轮新出现的。美术常把半透明全屏参考图留在 prefab 里（默认隐藏、图没提交）→ 删掉 |
| 9 | 项目守卫测试 | 用 MCP `run_tests` 跑涉及这些 prefab 的 EditMode 测试（grep 测试目录里出现的 prefab 名）；图集 / 资源清单类守卫不会出现 prefab 名，按程序集整跑 | 新失败逐条归因；与 prefab 无关的单独标注。守卫遇到第一个失败就停的，修掉后重跑 |
| 10 | 可点击、可裁剪 | `InteractAudit.cs`（静态，有旧版快照时标「原有 / 已不存在」）：`BLOCKED` 按钮中心最上层接射线的不是按钮自己；`MASKOFF` 列表里 `maskable=false`；`OVERSIZE` 列表项里接射线、无点击处理、比所在项大的装饰图 | 结论用 Play 里**真实点击**（`simulate_mouse_click`）证实，`onClick.Invoke()` 会绕过遮挡。运行时由代码二选一显示的按钮会被静态报 BLOCKED，回代码确认谁切换 |
| 11 | 图集与资源清单 | `git diff --name-status` 的新增 / 删除图片；Unity 导入后资源仓库里冒出来的 `*.spriteatlas` 改动 | 新图放进按文件夹打包的图集目录但美术没提交图集文件 → Unity 自动补打包列表，这是该提交的内容，不能还原。按清单打包的图集：新图加进清单，没人用的图摘掉 |
| 12 | 横版改竖版 | 窗口类里的横版缩放常量；prefab 里纵向拉伸、`sizeDelta` 为负的节点 | 美术已按竖版 1:1 重排 → 去掉代码缩放并同步测试期望；纵向拉伸、`sizeDelta.y` 为负的节点在竖版画布上会被拉长，改为固定高度 |
| 13 | 代码写入的文字节点换了组件类型 | `prefab_audit.py refs`（报旧版 `UI.Text`）；对照 `OnBind` / 开窗代码里每个按类型取组件的路径 | 取不到只打 Error 的框架会**静默失败**：价格停在 prefab 写死的值。运行时拿真实数据核对（价格对照商店配置） |
| 14 | 模块专用多语言组件 | `prefab_audit.py refs --forbid-loc-under <模块路径片段>` | 某模块文字由自己的组件管（不该挂宿主多语言组件）时，美术挂上的宿主组件多余，且可能在 Awake 依赖全局单例导致测试抛异常 |
| 15 | 容器被默认隐藏 | 第 3 项 `ACTIVE` 行，再 grep 代码有没有 `SetActive(true)` | 代码只填内容、不负责打开的容器被隐藏 → 功能没了。**先在 Play 里临时打开看一眼**：可能是美术有意避开重叠 |
| 16 | 非界面美术资源（Spine 等） | 受影响模块 EditMode 全量；Spine 逐套核动画名、atlas 页名、材质 shader | 代码按名字播动画，名字不对 spine-unity 直接抛异常；atlas 页名漏编号留下孤儿贴图；自动生成的 `Spine/Skeleton` 材质不是工程统一材质 |
| 17 | 美术覆盖了程序的修复 | BASE 已含程序修复时，看修过的节点是否又被改回 | 美术在旧本地版本上改完整文件提交 → 程序修复被改回。重新修，并在清单里提醒美术先拉最新 |
| 18 | 编辑器里看不到的运行时元素 | Play 里看带 Spine 标题、运行时克隆节点的面板，读包围盒是否相交 | 美术看不到 Spine 动画和运行时生成的节点，会把新元素摆到它们的位置 |
| 19 | 按钮的子图与锚点 | 按钮下子图中心是否落在按钮范围内；锚在会拉伸的全屏 Root 边上的小元素 | 子图挂错按钮 → 点它触发错的按钮；锚在拉伸容器边上的元素换宽高比就偏出面板 |

## 4. 运行时审查

1. 进 Play（项目默认语言、测试号）。刚进 Play 几秒内的白块通常是资源还在加载，过几秒再截。
2. 打开界面：先跑 `snippets/review/OpenViews.cs`（自动按常见 UI 管理器约定找打开方法，找不到会列候选）；确认好的打开方式记进项目记忆。玩法内面板尽量按真实流程打开（价格、礼包由真实逻辑写入）。
   - 片段里别写 `"\\n"` 这种字符串字面量（有的 MCP 严格路径检查会误拦），换行用 `Replace('\n', '~')`。
3. **读数值，不能只看截图**：Game 视图可能被压得很窄。直接读 TMP 文本、激活状态、`verticalNormalizedPosition`、换算后的包围盒，跟期望值比对。
4. 占位值检查：`RuntimeLocPlaceholder.cs` 列出激活中的 `LocalizationText(id=0)` 及强制文本（项目没有该组件时不适用）。显示值等于 prefab 占位值（如 1234、"Large Bundle"）就是写回问题。
5. 每个有问题的界面截一张图留证；字体问题至少看一遍中文，条件允许再看日 / 韩。
   - 有交互的界面用**真实点击**走关键路径，留意返回里的 `blockedBy`。
   - 列表滚到首尾，看有没有图片没被裁剪。
   - 改布局的试验（原则 8）只在运行时改值，退出 Play 自动消失。
6. 退出 Play 后检查资源仓库工作区：TMP 动态字体、被运行时改写的共享材质常有浮点数变化，不是本次修改，`git checkout` 还原。按文件夹打包的图集自动补的打包列表不算副作用（第 3 节第 11 项）。

## 5. 结论与文档

产出 `<项目文档目录>/<序号>-美术换皮审查-<日期>.md`（项目没有文档目录时放仓库 `docs/`），默认 Markdown，并用 `SendUserFile` 发给用户：

- 头部：范围（资源仓库区间、提交数、prefab 数、主仓指针）、方法（静态 / 绑定 / 代码路径 / 运行时 / 测试各做了什么）
- **结论摘要表**：`# | 问题 | 严重度 | 处理方（程序 / prefab / 策划 / 美术） | 状态`，最严重的在前，严重度写实测后果
- 需要改代码的地方：现象（实测）、原因（节点 / 组件 / 代码行）、改法、改动量
- 只需改 prefab 的地方：prefab、改动、后果、怎么改
- 需要决策的地方（推荐 + 备选）
- 已核实不受影响：要写，让人知道哪些不用再查
- 未覆盖 / 待确认：没进的流程、没测的语言、没上真机、文案疑问
- **给美术的修改清单**：字体问题（`LocFontReport.cs` 输出）与其他需要美术改的 prefab 项，能单独转给美术
- 附录：节点清单（`prefab_audit.py locfont --appendix`）
- 修复之后：摘要表「状态」改「已修」，文末追加「修复记录」（代码、测试、prefab 各项注明本轮 / 原有、图集、验证结果、没修的项）

## 6. 修复规范

### 6.1 代码侧
- 只做适配：组件类型放宽到共同基类（如 `HorizontalOrVerticalLayoutGroup`），写死方向的逻辑改成按布局算或按 `ScrollRect` 方向分支。
- 改了测试依赖的版式，同步改测试：按当前 prefab 断言，不能为通过而删断言。
- 框架级兜底只在影响面广、语义安全时做，并记进项目事实 / 决策。

### 6.2 prefab 侧
- **只用 Unity Editor API** 修改（`PrefabUtility.LoadPrefabContents` → 改 → `SaveAsPrefabAsset` → `UnloadPrefabContents`），编辑器开着时不手改 YAML。整文件恢复到某提交可以 `git checkout <rev> -- <file>`。
- **依赖顺序**：先改被嵌套的源 prefab 和 Variant 的基础 prefab，再改外层；内层刚改过的外层留到下一轮（重新导入后才看到新值）。脚本写成可重复跑，跑到「本轮零改动」为止。
- **字体问题（有规范字体约束的项目）默认只统计、交美术改**：用 `LocFontReport.cs`（Unity 侧，带建议字体和预设材质）或 `prefab_audit.py locfont --appendix`（git 侧）出清单写进「给美术的修改清单」，美术改完重跑复核到清零（只剩注明的「原有」）。建议规则（DragonCD3 体系）：
  1. 只针对挂了 `LocalizationText` 的文字：换成 `TMP_Font_Normal`（标题可用 `_Title`），切语言才生效。没挂的（自带按语言换字体的组件、纯数字）不强制。
  2. 材质按「换字体前」美术用的 `LocaleFont_En SDF <X>` 映射到美术维护的 `TMP_Font_Normal 3<X>` 预设；`Shadow` / `Describe` / `Title` 用 `OutLine Black`；其余用默认材质。映射表在 `LocFontReport.cs` 顶部，美术新增预设时同步。
  3. 动态文本上新挂的 `LocalizationText(id=0)` 建议删组件。
  - **不要由程序生成效果材质**（效果材质由美术维护，缺预设时列出请美术补）。程序直接改字体曾把材质退回换皮前、丢了美术的描边阴影 —— 这是交美术改的原因。美术改完用 `FxCompare.cs` 对比美术版，把效果类型不一致的节点反馈确认。
  - 规范字体 SDF 边距小时粗描边、远投影会被压薄，要一致只能重烘焙字体，需美术评估。
- **布局重排**：九宫格底图上下边框占满时高度只能整体缩放（同时加宽 `sizeDelta` 保持显示宽度）；重排后在最短屏（如 16:9）确认不出屏。
- **列表改为滚动加遮罩**：列表项里所有图片打开 `maskable`；比卡片大的装饰图关 `raycastTarget`；锚点跟着所在底栏 / 容器走。
- **Spine 资源**：动画名不对改 json 里 `animations` 的键（改完 `json.loads` 校验）；文件改名用 `git mv` 连同 `.meta`；材质用 Editor API 照同组正常的那套改。
- **图集**：新图加进图集并重新打包（`SpriteAtlasExtensions.Add` / `Remove` + `SpriteAtlasUtility.PackAtlases`），没人用的图摘掉；项目有未用资源清单的同步登记。
- 保存会让 Unity 重序列化整个文件，可能出现与改动无关的等价大 diff，提交说明里写明。

### 6.3 验证
